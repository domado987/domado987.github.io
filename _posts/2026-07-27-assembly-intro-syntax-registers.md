## **어셈블리 언어**

### 어셈블리 언어 :

CPU가 직접 이해할 수 있는 0과 1의 기계어를 사람이 읽을 수 있는 **문자** 형태로 1:1 대응시킨 저레벨 프로그래밍 언어다.

고급 언어로 작성한 코드는 컴파일 과정을 거쳐 어셈블리 형태를 거치고, 최종적으로 0과 1의 기계어로 변환되어 CPU에 입력된다. 이때 어셈블리를 기계어로 바꾸는 프로그램을 어셈블러(Assembler)라고 부른다.

- **기계어:** CPU가 직접 이해하는 0과 1로 된 언어
- **저급 언어 (어셈블리):** 기계어의 0과 1을 사람이 볼 수 있게 단어로 바꾼 언어 (하드웨어 직접 제어)
- **고급 언어 (Python, C, Java):** 사람이 이해하기 쉬운 영어/수학식 형태의 언어 (번역 거쳐 실행)

아래 예시는 고급 언어 → 저급 언어 → 기계어 순서로 변환한 결과다.

`x = a + b` → `MOV EAX, [A]`, `ADD EAX, [B]` → `10111000 00000001 …`

고급 언어는 추상화된 환상(Abstraction)을 제공하지만, 컴퓨터는 실제로 어셈블리 명령어를 실행한다.

### 어셈블리 언어를 배워야 하는 이유?

1. **컴퓨터가 실제로 뭘 하는지 볼 수 있다.**<br>
C나 파이썬 같은 경우 인간이 보기엔 편하다. 하지만 컴퓨터 내부에서 정확히 어떤 동작으로 실행되고 있는지는 알 수 없다. 어셈블리를 알게 되면 최소 단위에서 컴퓨터가 어떻게 동작하는지 눈으로 확인할 수 있기 때문에, 프로그램에 대한 이해의 깊이가 달라진다.
2. **보안(리버싱, 포너블)의 기본 언어다.**<br>
보안을 하는 입장에서 어셈블리어를 읽는 과정은 필수적이다. 리버싱은 방정식을 푸는 것처럼 "key"를 찾아내는 게 목적이기 때문에, 프로그램을 최소 단위에서 하나하나 따라가며 역추적해야 한다. 포너블은 프로그램이 실행되는 동안 "메모리"의 변화를 읽어야 하는 경우가 많기 때문에, 결국 어셈블리 없이는 접근 자체가 불가능하다.
3. **디버깅 능력이 달라진다.**<br>
C언어로 분명 코드를 제대로 짰는데도, 이해가 안 가는 지점에서 오류가 나는 경험이 꽤 자주 있다. 개인적으로는 자료형 사용에서 오류가 생기거나, 과도한 재귀함수 호출로 스택과 힙이 충돌하는 경우가 많았다. 어셈블리를 알게 되면서 이런 버그가 정확히 어떤 원리로 생기는지 이해할 수 있게 되었다.

## NASM / MASM 어셈블러

### nasm / masm

nasm과 masm은 모두 어셈블리어를 기계어로 변환하는 어셈블러다.
그러나 둘은 만든 주체와 목적에서 차이가 존재한다.

**공통점**

둘 다 Intel 문법을 사용한다. Intel 문법이라고 하면 목적지(destination) 피연산자가 먼저 오는 방식을 말한다.
또한 둘 모두 x86/x64 아키텍처를 대상으로 하며, 매크로/조건부 어셈블리/섹션 지시어 등을 지원한다.

**차이점**

| 항목                        | NASM                                 | MASM                                                          |
| --------------------------- | ------------------------------------ | ------------------------------------------------------------- |
| 라이선스/주체               | 오픈소스                             | Microsoft 독점                                                |
| 플랫폼                      | Linux, Windows, macOS 크로스플랫폼   | Windows 전용                                                  |
| 통합 환경                   | 텍스트 에디터 + 커맨드라인 위주      | Visual Studio와 깊게 통합                                     |
| CTF/보안 커뮤니티 사용 빈도 | 매우 높음 (특히 shellcode 작성)      | 낮음 (Windows 드라이버/커널 문제 한정)                        |

간단하게 말해, NASM의 경우 어디서든 돌아가는 범용적인 어셈블러고, MASM의 경우 Windows 전용 어셈블러라고 생각하면 된다. 보안 공부를 하는 입장에서는 NASM을 주로 접하고 공부하게 된다.

## **어셈블리 기본 문법:** Intel 구문

### Intel 구문 / AT&T 구문

같은 기계어를 표현할 때, Intel 구문과 AT&T 구문의 두 가지 표현법이 존재한다.<br>
실제 실행되는 명령은 동일하면서도 읽고 쓰는 표현법이 다른 것이다.<br>
이렇게 둘이 존재하는 이유는 운영체제와 프로그램에 따라서 지원하는 구문이 다르기 때문이다.<br>
Intel 구문의 경우 Intel/Microsoft 계열의 전통적인 표기법으로 NASM, MASM, IDA, Ghidra 등 많은 프로그램에서 이 표현을 사용하게 된다.<br>
AT&T 구문의 경우 유닉스/GNU 툴체인의 기본값이다. 역사적으로 유닉스 시스템에서 컴파일러가 이 문법으로 어셈블리를 뽑아냈기 때문이다.<br>
둘 모두 표기법과 읽는 방법을 알아야 하나, 보안을 일단 시작하는 입장에서는 이해가 쉽고, 대부분의 사람들이 사용하며, 주로 보게 될 Intel 구문을 공부하는 것이 좋다.

### Intel 구문 집중 정리

1. **기본 구조**
    
    `명령어 목적어, 소스` 
    
    "목적지(destination)가 먼저, 소스(source)가 나중” - 이것만 기억하면 절반은 끝난다.
    
2. **레지스터와 상수 (접두사 없이 그대로)**
    
    레지스터를 표현하는 방법에서는 접두사가 존재하지 않는다.
    
    ```nasm
    mov rax, rbx    ; 64bit 전체 복사
    mov eax, ebx    ; 32bit (상위 32bit는 자동으로 0 클리어됨)
    mov al, bl      ; 하위 8bit만
    ```
    
3. **메모리 참조 (대괄호 [ ])**
    
    포인터 역참조는 대괄호로 표시한다.
    
    ```nasm
    mov eax, [ebx]          ; ebx가 가리키는 주소의 값을 eax로
    mov [eax], ebx          ; ebx의 값을 eax가 가리키는 주소에 저장
    mov eax, [ebp - 4]      ; ebp-4 주소의 값 (지역변수 접근에 흔함)
    mov eax, [ebp + 8]      ; ebp+8 주소의 값 (함수 인자 접근에 흔함)
    ```
    
4. **크기 지정자**
    
    레지스터끼리는 이미 크기가 명확하지만, 메모리 주소에 즉시값을 넣을 땐 크기를 명시해야 한다.
    
    ```nasm
    mov byte [eax], 1        ; 1바이트
    mov word [eax], 1        ; 2바이트
    mov dword [eax], 1       ; 4바이트
    mov qword [eax], 1       ; 8바이트
    ```
    

참고로 mov A, B의 경우, B의 값을 A에 할당하라는 뜻이다 (A = B).

## **핵심 레지스터 정복:** 범용 레지스터, 세그먼트 레지스터, 플래그 레지스터

레지스터의 대략적인 설명은 1편에 기록해두었다.<br>
레지스터는 각각 이름과 역할이 존재한다. 다만, 모든 것을 알고 암기할 수는 없다.<br>
아래는 아주아주 필수적인 레지스터들의 종류에 대해서 설명하겠다.

### 범용 레지스터

| 레지스터      | 왜 필수인가                                                                                                                         |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **rsp / esp** | 스택 포인터. BOF의 모든 것이 이 값을 어떻게 덮느냐의 싸움. `pop rsp`가 있으면 스택 피벗 가능                                        |
| **rbp / ebp** | 스택 프레임 기준점. 리턴 주소는 항상 `[rbp+8]` (x64) 위치. 카나리는 `[rbp-8]` 근처                                                  |
| **rip**       | 프로그램 카운터. **결국 모든 pwn의 목표는 rip를 원하는 주소로 덮는 것**. <br>ROP/ret2libc/shellcode 전부 rip 제어가 최종 목적<br>rip는 mov를 통한 값 수정이 불가능          |
| **rax**       | 함수 리턴값 + **syscall 번호**. `execve` 쓰려면 rax=59(x64) 세팅 필수                                                               |
| **rdi**       | x64 함수 **1번째 인자**. `pop rdi; ret` 가젯은 ROP에서 가장 많이 찾게 되는 가젯  |
| **rsi**       | x64 함수 2번째 인자. `read`, `write`, `execve`의 2번째 인자로 자주 등장                                                             |
| **rdx**       | x64 함수 3번째 인자. syscall에서 세 번째 인자(예: `read(fd, buf, size)`의 size)                                                     |

위 7개의 레지스터 (`rsp, rbp, rip, rax, rdi, rsi, rdx`) 는 진짜 눈 감고도 역할이 튀어나와야 한다..만 위의 설명만을 읽고서 이해할 수는 없을 것이다. 이해한다면 아마 당신은 수퍼 천재인 것이다.<br>
rsp, esp, rbp, ebp, rip의 경우 3편과 4편에서 자세하게 설명할 것이고, 나머지 레지스터의 경우 5편에서 자세히 설명할 예정이다.

### 세그먼트 레지스터

과거 세그멘테이션 메모리 모델의 잔재로, 현대 64bit 리눅스에서는 거의 사용하지 않는다. 
다음 한 가지 레지스터만 알고 있으면 된다.

**fs : TLS(Thread Local Storage) 접근**
`fs:[0x28]` = 스택 카나리 저장 위치. 카나리 우회/리크 문제에서 100% 등장

BOF를 방지하기 위한 기법으로 스택 카나리(Canary)라는 것이 존재한다. 
스택이 덮어씌우는 것을 관찰하고 방지하는 것이 목적이므로 Canary의 값은 항상 랜덤 값을 가지는 fs:[0x28]에서의 값을 가져오게 된다.

```nasm
; ── 프롤로그 (함수 시작 시) ──
mov rax, fs:[0x28]     ; TLS 영역(fs:0x28)에서 랜덤 카나리 값을 읽어옴
mov [rbp-8], rax       ; 읽어온 카나리 값을 스택 지역변수 자리(rbp-8)에 저장

; ...
; 함수 본문 실행 (여기서 버퍼 오버플로우가 발생하면 rbp-8에 저장된 카나리가 덮어씌워짐)
; ...

; ── 에필로그 (함수 종료 직전) ──
mov rax, [rbp-8]       ; 스택에 저장해뒀던 카나리 값을 다시 꺼내옴
xor rax, fs:[0x28]     ; 원본 카나리(fs:0x28)와 XOR 연산
                        ; → 두 값이 같으면 결과는 0, 다르면 0이 아님
je  skip_fail           ; XOR 결과가 0(ZF=1)이면 = 카나리가 안 변함 → 정상, skip_fail로 점프
call __stack_chk_fail   ; XOR 결과가 0이 아니면 = 카나리가 변조됨(BOF 발생) → 프로그램 강제 종료
skip_fail:
; 정상적으로 함수 리턴 진행 (ret)
```


### 플래그 레지스터

**ZF (Zero Flag)** 하나만 정확히 알고 있어도 충분하다.

`cmp` 후 `je`/`jne` 판단의 핵심. 인증 체크, 조건 분기 우회의 90%가 이 플래그 하나
