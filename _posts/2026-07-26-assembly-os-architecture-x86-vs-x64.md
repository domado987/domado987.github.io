## **컴퓨터 핵심 구조:**
### **컴퓨터란**
**컴퓨터**는 방대한 **정보(데이터)를 저장하고 검색하고 처리**하는, 프로그래밍이 가능한 정보 처리 시스템, 전자적 기계 장치 또는 자동으로 계산(연산)을 수행하고 기계장치(machines)들을 제어하는 전자 기기다.<br>
컴퓨터에는 다시 말해서 저장과 검색과 처리의 기능을 할 수 있어야 한다.<br>
특히 컴퓨터는 처리의 부분에서 그 무엇보다 빠르게 연산이 가능하다는 특징이 존재한다.<br>

### **컴퓨터 내부 장치**
컴퓨터 내에는 **다양한 장치(부품)이 존재**한다.<br>
이는 크게 입력 장치, 출력 장치, **중앙처리장치**, 저장 장치로 나눌 수 있다.<br>
특히 어셈블리 언어를 이해하기 위해서는 CPU, 메모리(RAM), 레지스터의 역할과 상호작용 과정을 잘 이해할 필요가 있다.<br>

### **CPU, 메모리, 레지스터**

**CPU (중앙처리장치)**<br>
CPU는 명령어를 해석하고 실행하는 컴퓨터의 두뇌 역할을 한다.<br>
크게 **ALU(산술논리연산장치)**, **CU(제어장치)**, **레지스터**로 구성된다.<br>
ALU는 덧셈, 뺄셈 같은 산술 연산과 AND, OR 같은 논리 연산을 수행하고, CU는 명령어를 해석해서 각 장치에 제어 신호를 보내는 역할을 한다.<br>

**메모리 (RAM)**<br>
메모리는 실행 중인 프로그램의 코드와 데이터를 임시로 저장하는 공간이다.<br>
CPU가 직접 접근할 수 있는 저장 장치 중 하나이며, 전원이 꺼지면 내용이 사라지는 **휘발성(volatile)** 특성을 가진다.<br>
프로그램이 실행되면 하드디스크나 SSD에 저장되어 있던 코드가 메모리로 올라오고, CPU는 이 메모리에 접근해서 명령어를 하나씩 읽어와 실행한다.<br>

**레지스터**<br>
레지스터는 CPU 내부에 있는 아주 작고 빠른 임시 저장 공간이다.<br>
메모리보다 훨씬 빠르지만 용량이 극히 작기 때문에, 현재 연산에 필요한 값이나 다음에 실행할 명령어의 주소 등을 담아두는 용도로 쓰인다.<br>
어셈블리 코드를 읽고 쓰려면 이 레지스터들의 이름과 역할을 아는 게 필수인데, 대표적으로 범용 레지스터(EAX, EBX 등), 스택 포인터(ESP/RSP), 베이스 포인터(EBP/RBP), 명령어 포인터(EIP/RIP) 등이 있다.<br>
이 레지스터들에 대한 자세한 설명은 2편에서 다룰 예정이다.<br>

**세 장치의 상호작용**<br>
프로그램이 실행되는 흐름을 아주 단순화하면 이렇다:<br>
1. 보조기억장치(SSD/HDD)에 있던 프로그램이 메모리(RAM)로 올라온다.<br>
2. CPU는 명령어 포인터(EIP/RIP)가 가리키는 메모리 주소의 명령어를 가져온다(Fetch).<br>
3. CU가 그 명령어를 해석한다(Decode).<br>
4. ALU가 실제 연산을 수행하고, 레지스터에 결과를 저장한다(Execute).<br>
5. 다음 명령어로 넘어간다.<br>

이 Fetch-Decode-Execute 사이클이 반복되는 게 바로 컴퓨터가 프로그램을 실행하는 원리이고, 어셈블리 언어는 이 사이클에서 CPU가 실제로 이해하는 명령어에 가장 가까운 형태의 언어다.<br>

> Fetch-Decode-Execute 사이클은 어셈블리와 리버싱을 이해하는 데 가장 기본이 되는 개념이라, 이후 함수 호출/스택 프레임 편에서도 계속 등장한다.
{: .prompt-tip }

## **운영체제(OS)의 종류와 커널:** Windows, Linux, macOS가 시스템 자원을 다루는 방식

### **운영체제란**
**운영체제(OS, Operating System)**는 컴퓨터의 하드웨어 자원(CPU, 메모리, 저장장치 등)을 관리하고, 응용 프로그램이 이 자원을 안전하고 효율적으로 사용할 수 있도록 중간에서 관리해주는 시스템 소프트웨어다.<br>
프로그램이 직접 하드웨어에 접근하는 게 아니라, 항상 운영체제를 거쳐서 자원을 요청하고 사용한다.<br>

### **커널(Kernel)**
**커널**은 운영체제의 핵심 부분으로, 메모리 관리, 프로세스 스케줄링, 하드웨어 제어 등 가장 근본적인 기능을 담당한다.<br>
사용자가 실행하는 일반 프로그램은 **유저 모드(User Mode)**에서 동작하고, 커널은 더 높은 권한을 가진 **커널 모드(Kernel Mode)**에서 동작한다.<br>
이 두 모드의 권한 분리는 보안에서 아주 중요한 개념인데, 프로그램이 시스템 자원에 직접 접근하지 못하게 막아서 시스템 전체가 망가지는 걸 방지하는 역할을 한다.<br>
나중에 다룰 **시스템 콜(syscall)**이 바로 유저 모드에서 커널 모드로 넘어가는 통로다.<br>

### **Windows, Linux, macOS 비교**

**Linux**<br>
오픈소스 커널이며, 서버·임베디드·보안 분야에서 압도적으로 많이 쓰인다.<br>
CTF나 시스템 해킹 공부를 할 때 기본 환경으로 삼는 경우가 많은데, 커널 소스가 공개되어 있어서 내부 동작을 직접 들여다볼 수 있다는 게 큰 장점이다.<br>
시스템 콜 규약으로는 **System V AMD64 ABI**를 사용한다 (5편에서 자세히 다룸).<br>

**Windows**<br>
NT 커널 기반이며, 소스코드가 비공개다.<br>
GUI 중심 생태계가 강하고, 리버싱/악성코드 분석 분야에서는 Windows 바이너리(PE 포맷) 분석이 핵심 스킬 중 하나다.<br>
함수 호출 규약도 Linux와 다른 **Microsoft x64 Calling Convention**을 사용한다.<br>

**macOS**<br>
**XNU**라는 커널을 쓰는데, 이는 Mach 커널과 BSD 커널 요소가 결합된 하이브리드 커널이다.<br>
Unix 계열이라 Linux와 비슷한 점이 많지만, 바이너리 포맷(Mach-O)이나 보안 모델은 또 다르다.<br>

> 세 OS 모두 결국 CPU와 메모리라는 같은 하드웨어를 다루지만, 시스템 콜 방식과 바이너리 포맷이 다르기 때문에 같은 어셈블리 지식이라도 OS마다 실전에서 적용하는 방식이 조금씩 달라진다.
{: .prompt-info }

## **32비트(x86) vs 64비트(x86-64):** 아키텍처 차이와 레지스터 확장(EAX vs RAX)

### **비트(bit) 수의 의미**
여기서 말하는 32비트, 64비트는 CPU가 **한 번에 처리할 수 있는 데이터의 크기**와, **메모리 주소를 표현하는 데 사용하는 비트 수**를 의미한다.<br>
32비트 시스템은 이론적으로 2^32(약 4GB)까지의 메모리 주소만 표현할 수 있는 반면, 64비트 시스템은 2^64라는 훨씬 큰 주소 공간을 다룰 수 있다.<br>

### **레지스터 확장: EAX → RAX**
x86(32비트)에서 x86-64(64비트)로 넘어오면서, 기존 32비트 레지스터들이 64비트로 확장됐다.<br>
대표적으로:<br>

| 32비트 | 64비트 | 크기          |
| ------ | ------ | ------------- |
| EAX    | RAX    | 32bit → 64bit |
| EBX    | RBX    | 32bit → 64bit |
| ESP    | RSP    | 32bit → 64bit |
| EBP    | RBP    | 32bit → 64bit |

이름의 접두사가 `E`(Extended)에서 `R`(Register 또는 quad-word를 뜻하는 표기)로 바뀐 걸 볼 수 있다.<br>
재미있는 점은 하위 호환성을 위해, RAX 레지스터의 하위 32비트만 쓰고 싶으면 여전히 EAX라는 이름으로 접근할 수 있다는 것이다. 이런 식으로 레지스터는 계층적으로 쪼개서 접근 가능하다 (예: RAX의 하위 16비트는 AX, 그 중 하위 8비트는 AL).<br>

### **범용 레지스터 개수 증가**
x86-64로 넘어오면서 기존 8개였던 범용 레지스터(EAX, EBX, ECX, EDX, ESI, EDI, ESP, EBP)에 더해 **R8~R15**라는 8개의 레지스터가 추가돼서 총 16개가 됐다.<br>
이는 함수 호출 시 매개변수를 레지스터로 더 많이 전달할 수 있게 해줘서, 스택을 덜 쓰고 더 빠른 연산이 가능해지는 효과가 있다 (5편 호출 규약에서 자세히 다룸).<br>

> 32비트와 64비트의 차이는 단순히 "숫자가 커졌다"가 아니라, 레지스터 구조·호출 규약·메모리 주소 체계 전반에 영향을 미친다. 이후 편들에서 다룰 스택 프레임, 호출 규약 내용이 전부 이 차이 위에서 갈라지므로 잘 기억해두자.
{: .prompt-tip }
